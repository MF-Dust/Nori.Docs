# 凭据与本地数据安全

这一页说明 Nori 如何保存 API Key、Token 等敏感设置，以及用户在备份和迁移时需要注意什么。

## 敏感配置如何保存

Nori 会对 API Key、Secret、Token、Password 等敏感配置进行本地加密后再写入数据库。

当前格式使用 **`nsec2:`** 前缀，底层采用 AES-256-GCM。和旧版相比，当前格式会把密文与对应的配置项绑定，减少密文被错误复制到其他配置项后仍能使用的风险。

旧版 **`nsec1:`** 数据仍可以读取，并会在后续保存过程中逐步迁移到当前格式。

Windows 旧版本曾使用 `enc:dpapi:` 格式。Windows 上仍保留兼容读取；把这类旧数据直接迁移到其他系统时，个别密钥可能需要重新填写。

## 主密钥保存在哪里

Nori 会优先使用系统提供的安全存储：

- Windows：DPAPI
- macOS：Keychain
- Linux：libsecret

如果系统安全存储不可用，程序会使用权限受限的本地文件作为备用方案。

::: tip 这层加密保护什么
它主要用于降低数据库文件被单独复制后直接泄露密钥的风险。如果其他程序已经拥有与你相同的系统用户权限，并且能够读取应用进程或本机密钥存储，这种本地加密不能替代操作系统本身的账户安全。
:::

## 前端不会回传明文密钥

主控制台读取设置状态时，不需要把已保存的完整 API Key 再发送回网页界面。界面通常只需要知道“是否已经配置”，从而减少敏感值在界面层暴露的机会。

## 数据库升级前的备份

当 Nori 需要升级本地数据库结构时，会先尝试创建迁移前备份。

为了避免损坏数据库或异常文件占满磁盘，单个迁移备份存在大小限制，同时只保留有限数量的最近备份。

## 诊断包不会包含什么

通过 Nori 导出的诊断信息采用白名单方式收集。聊天内容、长期记忆正文、提示词、录音、API Key、数据库文件和真实用户数据路径不会作为常规诊断内容打包。

## 备份建议

当前正式版的数据都位于 Nori 程序根目录的 `data` 文件夹中。需要备份时，保留整个 `data` 文件夹即可覆盖绝大多数用户数据；需要完整搬家时，直接保留整套 Nori 根目录更省事。
