# Nori 是怎样组成的

这一页给想进一步了解 Nori 的用户一个整体认识，只保留和使用体验、兼容性有关的结构，不展开内部实现细节。

## 整体结构

Nori 可以理解成几部分协同工作：

| 部分 | 主要作用 |
| :--- | :--- |
| **桌面宿主** | 管理主窗口、首次运行窗口、托盘和桌面 Live2D 角色。 |
| **Live2D 桌宠** | 负责模型渲染、动作、表情、拖动、视线跟随和点击穿透。 |
| **主控制台** | 提供聊天、设置、模型、记忆、插件、MCP 和诊断等界面。 |
| **AI 与记忆服务** | 负责模型连接、对话、长期记忆、提醒、MCP 与语音等功能。 |
| **本地资源服务** | 在本机为主控制台提供界面资源、本地模型和临时音频数据。 |
| **插件系统** | 加载 `.noripack` 插件，并向 Nori 增加工具、窗口或聊天卡片。 |

## 为什么会看到多个窗口

Nori 会把不同用途的界面分开处理：

- **首次运行窗口**：第一次启动时出现，用来完成基础设置。
- **初始化窗口**：负责启动过程中的加载提示。
- **主控制台**：聊天和设置中心。关闭按钮通常只是隐藏窗口，Nori 仍会在后台运行。
- **桌宠窗口**：专门显示 Live2D 角色。

这样做可以让桌宠保持透明和轻量，同时让聊天、语音、设置等内容放在更适合的控制台中。

## 为什么 Nori 需要本机网络地址

主控制台会通过仅限本机访问的回环地址加载界面资源、本地模型和临时音频。

它不会因此把这些内容公开到局域网。Nori 会限制访问来源，并为内部资源使用随机路径。TTS 和录音等临时媒体也使用短时或一次性的访问方式。

## 正式版为什么有一个最外层 Nori 入口

当前发布包使用最外层的 `Nori` 启动入口选择实际运行版本。

普通用户只需要运行：

- Windows：`Nori.exe`
- Linux：`Nori`
- macOS：`Nori.app`

内部的 `.current` 和 `app-*` 目录属于程序自己的版本结构，不需要手动进入。

## 数据目录

当前正式版的新数据统一保存在：

```text
<PackageRoot>/data/
```

旧版系统用户目录只用于迁移历史数据。当前版本不会继续把新数据分散写回旧目录。

## 主控制台和桌宠怎样互相配合

主控制台与桌面宿主之间有专门的通信桥。用户在设置中切换模型、调整桌宠、发送消息或播放语音时，主控制台把请求交给宿主处理，再把结果更新回界面。

语音播放也由主控制台统一承载，因此主窗口隐藏后仍可以继续保持音频状态。

## 插件怎样接入

NPS 2.0 插件可以提供自己的动作和界面。启用插件后，Nori 可以把插件动作加入 AI 工具列表；插件也可以提供独立窗口或聊天卡片。

插件与主程序之间有独立的通信边界，但插件本身仍属于受信任的本机扩展，安装来源需要由用户判断。
