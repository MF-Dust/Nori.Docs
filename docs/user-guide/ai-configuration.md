# 连接 AI 模型

想和 Nori 进行 AI 对话，需要先连接一个可以使用的模型服务。它可以来自云端服务商，也可以是你自己在本机运行的兼容服务。

## 开始前需要准备

根据你准备使用的服务，通常需要：

- 一个可用的模型服务。
- 服务商提供的 API Key，如果该服务需要。
- 想使用的模型名称。

::: info Nori 不附带大语言模型权重
安装完成后，桌宠和本地界面可以直接使用；AI 对话需要另外连接模型服务。
:::

## 1. 打开 AI 设置

进入 **设置 → AI**：

<UiAiSettingsPreview />

## 2. 选择服务类型

当前可以选择：

| 服务类型 | 适合的情况 |
| :--- | :--- |
| **OpenAI** | OpenAI Chat Completions，以及兼容这套接口的第三方或本地服务 |
| **OpenAI Responses** | 使用 Responses API 的服务 |
| **Anthropic** | Anthropic 官方接口 |
| **Google** | Google Gemini 接口 |

如果服务商写明自己提供“OpenAI 兼容接口”，通常选择 **OpenAI** 即可。

## 3. 填写连接信息

最常见的几项是：

- **Base URL**：服务地址。使用官方接口时通常可以保留默认值。
- **API Key**：服务商提供的访问密钥。
- **模型**：可以先获取模型列表，再从可用模型中选择。

模型名称会随着服务商更新，所以文档不会长期写死某个推荐模型名。

::: tip API Key 会怎样保存？
保存后，界面不会再次显示完整明文。Nori 会使用本地加密格式保存敏感配置。想了解更多可以查看 [凭据与本地数据安全](../reference/security-spec.md)。
:::

## 4. 测试连接

填写完成后，先使用 **测试连接**。

测试成功后，就可以回到聊天页面尝试发送一条消息。

如果测试失败，可以依次检查：

- Base URL 是否填写正确。
- API Key 是否仍然有效。
- 当前网络能否访问服务商。
- 所选模型是否仍然可用。
- 使用本地服务时，服务是否已经启动。

测试连接只会发送用于确认服务可用性的短请求，不会把聊天历史或长期记忆当作测试内容发送。

## 使用本地 Ollama 等兼容服务

如果本地服务提供 OpenAI 兼容接口，可以选择 **OpenAI**，再填写本机地址和模型名。

以 Ollama 的 OpenAI 兼容端点为例，常见地址是：

```text
http://127.0.0.1:11434/v1
```

具体模型名称以本机实际安装的模型为准。是否需要 API Key 也由本地服务本身决定。

## 自定义人设

AI 设置中可以添加自定义人设，用来补充称呼、语气或角色偏好。

这部分会参与后续对话，因此不要填写密码、Token 或其他没有必要交给模型的敏感信息。

## 长期记忆的 Embedding

长期记忆可以单独配置 Embedding 服务，它和聊天模型互不绑定。

第一次使用时可以先把普通聊天配置好。需要长期记忆后，再继续设置 Embedding 即可。

🎉 连接测试通过以后，Nori 已经可以进行文字对话。想让回复直接念出来，可以继续阅读 **[开启语音](./voice-and-speech.md)**。
