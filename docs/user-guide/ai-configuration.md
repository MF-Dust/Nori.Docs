# AI 大模型接入配置

Nori 本身不附带大语言模型权重。要使用聊天功能，需要连接一个可用的模型服务，或者连接你自己在本机运行的兼容服务。

## 当前支持的接口类型

在 **设置 → AI** 中，当前可以选择：

- **OpenAI Chat Completions**
- **OpenAI Responses**
- **Anthropic**
- **Google**

其中 OpenAI 兼容模式也可以用于很多提供兼容 API 的第三方服务和本地服务。

## 最常用的配置项

### 服务类型

按照服务商实际提供的 API 协议选择。不要只根据模型名称猜协议。

### Base URL

填写服务商提供的 API 地址。Nori 会为 OpenAI、Anthropic 和 Google 协议提供默认地址；使用第三方兼容服务或本地服务时，可以改成对应地址。

### API Key

填写服务商提供的访问密钥。保存后界面不会重新显示完整明文，只会记录“已经配置”的状态。

当前版本会使用本地加密格式保存敏感配置，详情见 [凭据与本地数据安全](../reference/security-spec.md)。

### 模型

配置好服务地址和密钥后，可以使用界面中的模型列表获取功能。服务商返回可用模型后，从列表中选择即可。

这样比在文档里长期写死某个模型名更可靠，因为第三方模型名称和可用状态会随服务商更新。

## OpenAI 兼容服务

如果服务提供 OpenAI 兼容 API，可以选择 **OpenAI** 协议并填写它给出的 Base URL、API Key 和模型。

本地 Ollama 等服务也可以通过兼容接口接入。以 Ollama 的 OpenAI 兼容端点为例，常见本机地址为：

```text
http://127.0.0.1:11434/v1
```

具体模型名称以你本机实际安装的模型为准。

::: tip 本地服务不代表完全不需要配置
Nori 仍需要知道服务地址和模型名。是否需要 API Key 取决于本地服务本身的要求。
:::

## Anthropic 与 Google

使用 Anthropic 或 Google 官方接口时，直接选择对应协议。Nori 会切换到相应的默认服务地址，并按照该协议读取模型列表和发送请求。

## OpenAI Responses

如果使用支持 Responses API 的服务，可以选择 **OpenAI Responses**。它与传统 Chat Completions 是两个独立的协议选项，切换后建议重新获取一次模型列表。

## 测试连接

配置完成后，先使用 **测试连接**。

测试只发送固定的短请求用于确认服务是否可达，不会把你的聊天历史或长期记忆作为测试内容上传。

如果测试失败，可以重点检查：

- Base URL 是否完整
- API Key 是否有效
- 当前网络是否能访问服务商
- 服务商是否仍提供所选模型
- 本地服务是否已经启动

## 自定义人设

AI 设置中可以添加自定义人设内容，用来补充称呼、语气或角色偏好。

这部分内容会参与后续对话，因此不适合填写密码、Token 或其他本来不需要交给模型的敏感信息。

## Embedding 设置

长期记忆还可以单独配置 Embedding 服务。聊天模型与 Embedding 配置彼此独立，可以使用不同服务、地址和模型。

如果只想先体验普通聊天，可以先完成聊天模型配置，再根据长期记忆需求处理 Embedding。
