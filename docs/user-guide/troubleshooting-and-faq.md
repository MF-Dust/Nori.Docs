# 常见问题与安全排障

这里整理 Nori 日常使用中最常见的启动、界面、AI 和语音问题。

## 启动后没有反应或直接退出

Windows 正式版应从解压目录最外层运行 **`Nori.exe`**。

当前发布包需要：

- ASP.NET Core Runtime 10 x64
- Microsoft Edge WebView2 Evergreen Runtime

如果缺少其中一项，主程序可能无法正常启动。

::: warning 不要运行内部槽里的程序
最新版发布包中会看到 `.current`、`app-*` 等内容。它们属于 Nori 的版本目录，日常使用时不需要进入里面运行 `Nori.Desktop.exe`。
:::

## 一直停留在加载界面

先尝试使用安全模式启动。安全模式会暂时跳过部分联网服务、插件自动加载、MCP 自动连接和 Live2D 自动模型加载，让主界面尽可能进入可修复状态。

Windows PowerShell：

```powershell
.\Nori.exe --safe-mode
```

Linux：

```bash
./Nori --safe-mode
```

修正设置或移除故障插件后，退出 Nori，再通过正常入口启动即可。

## 桌宠突然不见了

可以尝试：

- 从系统托盘重新显示桌宠。
- 打开主控制台，确认桌宠没有被手动隐藏。
- 如果之前把桌宠拖到了屏幕边缘，重新唤出后再调整位置。

Windows 的模型区域点击穿透已经在当前主分支恢复。Linux Wayland 因系统协议限制，点击穿透和全局鼠标跟随会采用降级行为。

## AI 对话提示网络错误

常见原因包括 API Key 无效、服务地址错误、模型名不可用、账号侧额度限制或网络无法连接服务商。

可以在 **设置 → AI** 中使用连接测试先确认当前配置是否可用。使用本地 Ollama 等服务时，也需要先确认本地服务本身已经启动。

如果网页浏览、天气等公开网络能力在“必须依赖系统代理才能联网”的环境中失败，这可能来自 Nori 的网络安全策略。当前开发分支已经加入允许公开网络请求跟随系统代理的可选设置，默认仍保持关闭。

## 有文字回复但没有声音

可以检查：

- 语音朗读是否开启。
- 当前 TTS 服务是否配置完整。
- 系统输出设备和 Nori 音量是否正常。
- 主控制台是否仍在运行。Nori 的语音播放由主控制台承载，即使窗口隐藏，程序本身也需要保持运行。

## 本地数据在哪里

当前正式版的数据目录位于：

```text
<解压后的 Nori 根目录>/data/
```

旧版 Windows 数据目录 `%APPDATA%\cn.erhio.noriDesktopPet\data` 现在只作为旧数据迁移来源使用。

如果要备份 Nori，最省心的方法是保留整个程序根目录，尤其不要遗漏 `data` 文件夹。

## 导出诊断信息

遇到难以判断的问题时，可以在主控制台的调试区域导出诊断信息。

诊断包只包含经过筛选的版本、平台、能力状态和脱敏日志等排障信息，不会主动打包聊天内容、长期记忆、提示词、录音、API Key 或数据库正文。

提交问题时可以前往 [Nori.Desktop Issues](https://github.com/MF-Dust/Nori.Desktop/issues)，附上复现步骤和诊断包。
