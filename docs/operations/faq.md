# 常见问题与故障排查 (FAQ)

本章节汇总了使用 Nori Desktop Pet 时的常见问题与快速自查方案。

---

## 1. 安装与启动问题

### Q1: 双击 `Nori.Desktop.exe` 后闪退或无任何窗口弹出？
- **排查原因**：系统中缺失必需的运行时依赖。
- **解决方法**：
  1. 确认已安装 [.NET 10 Desktop Runtime (x64)](https://dotnet.microsoft.com/download/dotnet/10.0)。
  2. 确认已安装 [Microsoft Edge WebView2 Evergreen Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。
  3. 打开终端尝试通过命令行执行 `.\Nori.Desktop.exe`，观察控制台输出的具体错误堆栈。

### Q2: 启动后界面一直转圈停留在加载界面？
- **排查原因**：资源加载超时或之前的配置文件发生损坏。
- **解决方法**：
  1. 使用安全模式启动：`.\Nori.Desktop.exe --safe-mode`。
  2. 进入「设置」检查各服务商配置是否正确。
  3. 在「调试」面板查看最新日志，确认是哪个端点或文件发生了阻塞。

## 2. Live2D 与桌宠交互问题

### Q3: 桌宠无法拖拽，或者点击桌宠穿透到了底下的桌面？
- **排查原因**：
  - 拖拽必须满足 `4px` 移动阈值。
  - 只有在模型可见的不透明像素区域内点击才会响应互动；若点击在模型完全透明的外围空白区域，系统会自动将点击事件穿透到底层桌面（Windows / macOS / X11）。
  - 若在 Linux Wayland 环境下，请参考 [跨平台支持矩阵](/operations/platform-matrix) 了解协议限制。

### Q4: 导入自定义 Live2D 模型后黑屏或报错？
- **排查原因**：模型文件结构不符合 Cubism 3/4 规范，或缺少必要贴图。
- **解决方法**：
  1. 确认 ZIP 压缩包内包含有效的 `*.model3.json`、`*.moc3` 以及对应的 `textures/` 贴图文件夹。
  2. 请勿在文件名中包含特殊控制字符或非法相对路径符号（如 `../`）。
  3. 优先使用控制台内自带的「导入本地模型」功能，避免手动随意向资源目录拷贝残缺文件。

## 3. AI 对话与语音问题

### Q5: 发送对话后提示网络错误或长时间无响应？
- **排查原因**：LLM Base URL 填写错误、网络超时或 API Key 余额不足。
- **解决方法**：
  1. 进入 **「设置」→「AI 设置」**，点击对应提供商旁的 **「测试连接」** 按钮。
  2. 观察返回的连通性诊断信息（如 `HTTP 401 认证失败` 或 `无法连接到远程服务器`）。
  3. 若使用本地 Ollama，确认 Ollama 后台服务正在运行且模型已下载（如 `ollama run deepseek-r1:8b`）。

### Q6: 收到回复但听不到语音声音？
- **排查原因**：全局音量为 0、TTS 未正确配置或 `main` 控制台进程被异常终止。
- **解决方法**：
  1. 检查 **「设置」→「语音」** 中的全局音量滑动条与自动朗读开关。
  2. 点击「测试发音」排查 TTS 服务商是否能正常合成音频。
  3. 确认主控制台窗口处于运行状态（最小化隐藏属正常状态，音频宿主常驻于其中）。

## 4. 数据与跨系统迁移问题

### Q7: 把 Windows 上的 `nori.db` 拷贝到 macOS / Linux 后提示 API Key 无效？
- **排查原因**：API Key 采用 `nsec1:` 加密，主密钥受 Windows 系统级 DPAPI 保护，其他操作系统底层无法直接解密 Windows 的 DPAPI 密文。
- **解决方法**：这属于预期内的安全隔离表现。只需在跨系统迁移后，重新在设置面板中填入一次 API Key 即可，其他历史聊天记录与记忆原子不会丢失。

### Q8: 如何向官方提交 Bug 反馈？
- **操作步骤**：
  1. 进入主控制台 **「设置」→「调试」**。
  2. 点击 **「导出诊断信息」**，获取已脱敏的安全诊断 ZIP 包。
  3. 前往 [GitHub Issues 仓库](https://github.com/MF-Dust/Nori-Desktop-Pet/issues) 提交工单并附上诊断文件。
