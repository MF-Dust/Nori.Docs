# 诊断与日志

遇到启动、模型、语音或插件问题时，Nori 可以导出一份经过筛选的诊断包，方便你自己检查，也方便在 Issue 中提供环境信息。

## 导出诊断信息

在 **设置 → 调试** 中找到 **导出诊断信息**。

<UiDebugPreview />

导出的 ZIP 只收集排障需要的有限信息，例如：

- Nori 版本
- 操作系统与架构
- 当前平台支持哪些桌面能力
- 经过脱敏和长度限制的运行日志
- Agent 调用的阶段、耗时与 Token 数量等统计信息

## 诊断包不会带上什么

常规诊断导出不会包含：

- 聊天正文
- 长期记忆正文
- 系统提示词或自定义人设
- API Key、Token 或密码
- SQLite 数据库
- 麦克风录音
- 本地模型资源
- 真实用户文件路径

因此提交诊断包和直接打包整个 `data` 文件夹不是一回事。遇到问题时，优先使用应用内的诊断导出。

## 日志在哪里

运行日志位于 Nori 数据目录下的诊断区域：

```text
<Nori 根目录>/data/diagnostics/logs/
```

调试设置中也提供打开日志目录和复制可见日志的入口。

## 日志会不会把密钥写进去

日志路径会主动避免记录 API Key、Token、请求正文和完整用户内容。网络错误一般只保留足以排障的状态和错误类型。

如果你使用的是第三方插件或自己修改过的开发版本，它们自己的日志行为仍需要单独判断。

## 提交问题时建议附上什么

通常这些信息已经足够：

1. Nori 版本和操作系统。
2. 能稳定复现问题的步骤。
3. 问题发生的大致时间。
4. 应用内导出的诊断 ZIP。

Issue 地址见 [Nori.Desktop Issues](https://github.com/MF-Dust/Nori.Desktop/issues)。
