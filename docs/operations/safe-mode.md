# 安全排障模式

如果 Nori 因插件、模型、网络服务或配置问题无法正常进入主界面，可以使用 `--safe-mode` 启动。

安全模式只在你主动添加启动参数时启用。程序不会因为一次普通报错就自行切换到安全模式。

## 怎么启动

Windows 正式版：

```powershell
.\Nori.exe --safe-mode
```

Linux 正式版：

```bash
./Nori --safe-mode
```

macOS 可以从终端为最外层 Nori 启动入口附加同样的参数。

源码调试时仍可以使用：

```bash
dotnet run --project Nori.Desktop -- --safe-mode
```

::: warning 正式版请使用最外层 Nori 入口
新版发布包中会看到 `app-*` 等内部版本目录。日常排障不需要进入内部目录运行 `Nori.Desktop`。
:::

## 安全模式会暂时停用什么

为了尽量减少启动过程中可能出问题的外部因素，安全模式会暂停或拒绝部分功能，包括：

- AI 对话和需要联网的服务操作
- MCP 自动连接与外部调用
- 主动行为、反思和部分后台记忆维护
- Live2D 模型自动加载
- 第三方插件加载
- 浏览器与桌面自动化
- 外部语音服务调用

这些限制只在当前安全模式会话中生效，不会把你原来的启用状态永久改掉。

## 安全模式下还能做什么

<UiDebugPreview />

主控制台和本地设置仍然可以使用，因此可以：

- 修改错误的 AI、语音或 MCP 配置
- 查看插件列表，并禁用或卸载故障插件
- 查看日志
- 导出脱敏诊断信息
- 检查本地模型和其他设置

安全模式下不会加载第三方插件，但插件管理页面仍可用于排障。为了避免在排障过程中再次引入新变量，启用新插件或重新安装插件等操作会受到限制。

## 修复完成后

关闭 Nori，再通过平时的入口正常启动即可。只要没有继续附加 `--safe-mode`，程序就会恢复正常功能。

如果仍然无法启动，可以将脱敏诊断包连同复现步骤提交到 [Nori.Desktop Issues](https://github.com/MF-Dust/Nori.Desktop/issues)。
