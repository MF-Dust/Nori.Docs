# Nori 是怎样组成的

这一页给想多了解一点 Nori 的用户一个整体认识。只保留和使用体验、兼容性有关的结构，不展开源码里的每个类和接口。

## 整体结构

Nori 2.x 可以简单理解成几部分：

| 部分 | 主要作用 |
| :--- | :--- |
| **Avalonia 桌面宿主** | 显示聊天、设置、记忆、模型管理、托盘和其他原生窗口。 |
| **Live2D 伴侣视窗** | 渲染角色，处理动作、表情、拖动、视线跟随和点击穿透。 |
| **AI 与 Agent** | 连接模型，组织上下文，并协调技能、MCP 和插件动作。 |
| **语音系统** | 连接 TTS / Whisper，并直接使用系统音频设备播放和录音。 |
| **本地数据** | 保存设置、数据库、记忆、模型、插件和日志。 |
| **插件运行时** | 加载受信任的 `.noripack` 插件，并把插件动作提供给 AI。 |

## 2.x 和旧版最大的区别

旧文档曾把主界面描述成网页前端加 WebView。

现在用户界面已经迁移到 Avalonia 原生窗口，语音也改为直接使用系统音频设备。Nori 日常运行不再需要为了主界面启动一个网页渲染层。

## 为什么会看到多个窗口

不同功能会分开显示：

- 首次运行向导
- 启动初始化界面
- 主窗口
- Live2D 伴侣视窗
- 设置、记忆、模型等按需功能窗口

Live2D 角色需要透明窗口和桌面输入能力，把它独立出来可以更好地适配 Windows、X11、Wayland 和 macOS。

## 为什么正式版有最外层 Nori 入口

发布包使用最外层的 `Nori` 启动入口选择当前可运行版本。

普通用户只需要运行：

- Windows：`Nori.exe`
- Linux：`Nori`
- macOS：`Nori.app`

内部的 `.current` 和 `app-*` 属于程序自己的版本槽，不需要手动进入。

## 数据目录

当前运行数据统一保存在：

```text
<PackageRoot>/data/
```

这个目录包含数据库、设置、本地模型、插件数据和诊断日志等内容。发布包本身不会预先带着用户数据。

## 语音怎样和 Live2D 配合

TTS 生成的 WAV 会由 Nori 直接送到系统声卡。播放时，程序从实际音频缓冲计算音量变化，再驱动 Live2D 嘴形。

因此隐藏主窗口不会让语音改走网页播放器。

## 插件怎样接入

Plugin API 2.0 插件是受信任的进程内 .NET 扩展。

当前第三方插件可以注册动作，让 Nori 的 AI 调用；宿主暂时没有开放第三方插件页面、独立窗口或聊天卡片。
