# 凭据与本地数据安全

这页说明 Nori 怎样保存 API Key、Token 等敏感设置，以及备份和迁移时需要注意的事情。

## API Key 怎样保存

Nori 会先加密敏感配置，再写入本地数据。

当前格式以 **`nsec2:`** 开头，使用 AES-256-GCM。密文会和对应的配置项绑定，避免把一段密文随意挪到另一个配置项后仍能被当作有效内容使用。

旧的 **`nsec1:`** 仍可以兼容读取。更老的 Windows 版本还可能留下 **`enc:dpapi:`** 数据。

## 加密主密钥放在哪里

Nori 会优先使用操作系统提供的安全存储：

- Windows：DPAPI
- macOS：Keychain
- Linux：libsecret

系统安全存储不可用时，程序会退回到权限受限的本地文件。

::: tip 这层保护的范围
本地加密主要降低“数据库文件被单独复制走后直接看到密钥”的风险。若其他程序已经拥有与你相同的系统账户权限，操作系统本身的账户安全仍然更重要。
:::

## 设置界面会重新显示完整密钥吗

不会。

已保存的密钥不会为了刷新设置页面而重新以完整明文展示。界面通常只需要知道“已经配置”，需要更换时再输入新的值。

## 插件为什么需要单独注意

第三方 `.noripack` 插件属于受信任的进程内 .NET 扩展，不是真正的安全沙箱。

因此安装插件前仍需要判断来源。Nori 会检查插件包路径和结构，但这些检查不能把未知插件自动变成可信代码。

## 数据库升级与备份

涉及数据库结构升级时，Nori 会尽量在迁移前创建受大小和数量限制的备份，避免异常迁移直接破坏唯一副本。

这不替代你自己的整机或 `data` 目录备份。

## 诊断包不会包含什么

应用内诊断导出采用白名单收集。聊天内容、长期记忆正文、提示词、录音、API Key、数据库文件和真实用户数据路径不会作为常规诊断内容打包。

## 跨平台迁移

普通数据可以随 `data` 一起备份；敏感配置还依赖各平台的安全存储。

尤其是旧版 Windows 的 `enc:dpapi:` 密文，搬到 macOS 或 Linux 后无法直接解密时，需要重新填写对应密钥。

## 备份建议

当前运行数据统一位于 Nori 根目录的 `data` 文件夹。只备份用户数据时保留整个 `data`；需要完整搬家时保留整套 Nori 根目录更省事。
