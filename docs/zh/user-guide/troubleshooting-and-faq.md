# 常见问题与安全排障

这里整理 Nori 日常使用中最常见的启动、桌面伴侣、AI 和语音问题。

## 双击后没有反应

Windows 正式版应从解压目录最外层运行 **`Nori.exe`**。

当前 2.x 正式包需要 **.NET Runtime 10**。主界面已经迁移到 Avalonia 原生窗口，不再需要为了 Nori 主界面额外安装 WebView2。

如果仍然没有窗口，可以先查看 [诊断与日志](../operations/diagnostics.md)。

## 一直停留在加载界面

先尝试安全模式：

```powershell
.\Nori.exe --safe-mode
```

Linux：

```bash
./Nori --safe-mode
```

安全模式会避开第三方插件、MCP 自动连接、外部语音和部分后台功能，适合判断问题是否来自扩展或联网配置。

## Nori 伴侣视窗没有显示

可以检查：

- 是否从托盘或主窗口隐藏了伴侣。
- 窗口是否被拖到屏幕边缘或其他显示器。
- 当前 Live2D 模型是否可以正常加载。

Windows 与 X11 的点击穿透能力较完整；Wayland 会因为协议限制采用兼容模式。

## AI 对话提示网络错误

常见原因包括：

- 访问凭据无效或过期
- Base URL 填写错误
- 模型名已经不可用
- 本地兼容服务没有启动
- 当前网络无法访问服务商

先到 **设置 → AI** 使用连接测试，可以更快区分配置问题和聊天本身的问题。

## 有文字回复但没有声音

2.x 的语音播放直接使用系统音频设备。

可以检查：

- 自动朗读是否开启
- TTS 服务是否配置完整
- 服务返回的是否是可解码 WAV
- 系统输出设备和音量是否正常
- Linux 的 ALSA 运行库是否可用

当前 TTS 包括 OpenAI、Gemini、MiniMax、IndexTTS-2、GPT-SoVITS 和 Custom HTTP。

## 麦克风不能录音

可以检查：

- 操作系统是否允许 Nori 使用麦克风
- Whisper 服务配置是否正确
- macOS 是否已经授予麦克风权限
- Linux 当前音频环境能否通过 ALSA `default` 设备录音

## 插件安装后启动异常

使用 `--safe-mode` 启动后，到 **设置 → 插件** 禁用或卸载最近安装的插件。

第三方插件属于受信任的进程内扩展，因此来源不明的插件不适合用“装上试试”的方式排查。

## 本地数据在哪里

当前运行数据统一位于：

```text
<Nori 根目录>/data/
```

搬家或更新前，保留这个目录即可覆盖绝大多数用户数据；想最省心时可以直接备份整个 Nori 根目录。

## 导出诊断信息

难以判断的问题可以在 **设置 → 调试** 导出诊断 ZIP。

诊断包不会按常规流程包含聊天正文、长期记忆正文、提示词、录音、访问凭据或数据库文件。

提交问题时可以前往 [Nori.Desktop Issues](https://github.com/MF-Dust/Nori.Desktop/issues)，附上复现步骤和诊断包。
