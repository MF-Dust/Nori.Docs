# 安全排障模式 (`--safe-mode`)

当遇到外部 API 异常阻塞、配置错误、网络死循环或显卡驱动冲突导致常规启动受阻时，Nori Desktop Pet 提供了极其可靠的 **安全排障模式（Safe Mode）**。

---

## 1. 触发方式与设计准则

::: tip 人工触发准则
`--safe-mode` **仅接受人工命令行启动**，应用发生异常退出时**绝不隐式、自动进入安全模式**。这确保了用户的日常正常使用体验不会因偶发的网络超时而被意外降级。
:::

### 启动命令

在终端或快捷方式目标中追加 `--safe-mode` 参数：

```powershell
# Windows PowerShell
.\Nori.Desktop.exe --safe-mode

# 开发者调试模式
dotnet run --project Nori.Desktop -- --safe-mode
```

---

## 2. 安全模式能力边界与受限行为

进入安全模式后，系统顶部将显示显眼的黄色安全模式状态横幅，并对所有外部不确定性依赖实施**硬切断（Fail-Closed）**：

| 子系统 | 安全模式下的状态与行为 | 设计目的 |
| :--- | :--- | :--- |
| **外部网络与 LLM** | **完全禁用**：Bridge 拦截所有聊天、连接探测与联网请求 | 防止错误的 API 配置持续产生超时阻塞或费用 |
| **MCP 外部进程** | **跳过自动连接**：仅允许在面板中查看与修改配置 | 防止恶意或故障的外部 MCP 进程拖垮应用 |
| **主动感知与反思** | **完全停用**：跳过 Proactive 调度、定时提醒与 Reflection 任务 | 杜绝后台并发任务对数据库的写入压力 |
| **Live2D 桌宠加载** | **跳过自动加载**：桌宠窗口保持轻量静默状态 | 隔离 OpenGL / 显卡驱动渲染崩溃问题 |
| **插件系统 (NPS 2.0)** | **完全禁用**：不创建任何插件 `AssemblyLoadContext` | 隔离第三方损坏插件 |
| **自动化子系统** | **完全禁用**：拒绝拉起 Edge 自动化浏览器 | 确保系统绝对安全 |

---

## 3. 保留的核心运维能力

<UiDebugPreview />

安全模式虽然切断了重型服务，但**完整保留了所有本地运维与修复工具**：

1. **核心 Web 控制台可用**：可正常打开主控制台与全部设置面板。
2. **本地配置修复**：可重新填写或纠正错误的 API Base URL、API Key、TTS 路径或模型配置。
3. **脱敏诊断导出**：可直接使用 **「设置」→「调试」→「导出诊断信息」** 生成白名单诊断包提交 Issue。
4. **日志查看与分析**：可即时查看当前与历史运行日志并执行复制。

---

## 4. 故障排查与退出步骤

1. 检查并修正导致异常的配置项（如删除非法的 MCP 服务、更换无法连通的 LLM 接口）。
2. 在调试面板导出诊断包（如需向社区求助）。
3. 关闭应用，**不带 `--safe-mode` 参数正常重新启动**即可恢复全功能运行。
